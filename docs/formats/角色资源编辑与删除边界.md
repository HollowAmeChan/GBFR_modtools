# 角色资源编辑、删除与网格导出边界

本文记录面向 Mod 制作的操作边界。结论来自 `pl1400` 工作区、完整解包样本、Blender 4.5.8 实际导入/导出和当前游戏 EXE 静态分析；“可删除”只表示引用契约允许，不表示删除后外观与原版相同。

## 操作结论

| 对象 | 当前结论 | 必须同时检查 |
|---|---|---|
| Mesh 对象 | 可以删除 | 删除后所有 LOD 的 Mesh/chunk、包围盒和 `.minfo` 表由导出器重建 |
| source 主骨架骨骼 | 不可删除或改索引 | MOT、蒙皮、CLP/CLH、SOP 都可能引用；新增骨只能追加 |
| CLP 节点 | 可以删除，但会取消该骨的物理解算 | 清理 `noUp/noDown/noSide/noPoly/noFix` 的悬空引用，骨骼本体仍保留 |
| CLP 连接 | 可以删除 | 动画覆盖文件不引用这些连接；删除只改变求解拓扑 |
| CLH 单个碰撞记录 | 只能按真实 `id_` 精确删除 | 动作 `CollisionId0..5` 和同 CLH 的 `capsule` 引用均不得悬空 |
| 整个 CLH 层 | 通常不能直接删除 | 所有 CLP 的 `useCollisionFlags_` 和全部动作 `FileId` 都必须解除引用 |
| Blender 材质槽/`.minfo` 材质项 | 当前不要单独删除 | chunk MaterialID、`.minfo` 材质数组及所有配色 MMAT 的材质数组必须同步重编号 |
| Blender 面材质分配 | 支持 | 材质必须有有效 `MaterialID`；导出会按材质重排三角形索引以生成连续 chunk |

## 动画覆盖物理的实际粒度

这里有两条不同通路，不能混称为“动画覆盖整个 cloth”：

1. MOT 可以直接给 cloth 骨骼写旋转/位移目标，CLP 求解器再用拓扑、物理参数与 `originalRate_` 等字段修正。删除 source 骨骼会破坏 MOT 索引；删除某个 CLP 节点则是让该骨从“动画目标 + 物理”退化为只保留普通骨骼动画，并非动画文件产生悬空 CLP 引用。
2. `_seq_edit_cloth.bxm` 的 `ClothTrack/Seq` 使用 `FileId` 选择 CLH 层，并用 `CollisionId0..5` 精确选择该层内的真实碰撞 ID。它不引用 CLP 节点，也不引用 `noUp/noSide` 等拓扑连接。

`pl1400_0002_0_seq_edit_cloth` 可直接看到同一个动作分别修改 CLH0 的碰撞 `0/1/4` 和 CLH5 的碰撞 `0`，因此粒度已经精确到单个 CLH 碰撞记录，不是整个 CLP，也不是只能整层 CLH 开关。

当前 EXE 的 Seq 读取函数位于 `0x1444DC2E0`（地址随游戏版本变化）。每条内部记录大小为 `0x34`：`FileId` 写入记录 `+0x0A`，六个 `CollisionId` 分别写入 `+0x0C..+0x20`。这与 1,820 个玩家角色 `_seq_edit_cloth.bxm` 的字段结构一致。删除碰撞前必须同时扫描动作引用和 capsule 链，不能把列表行号当碰撞 ID。

## 平滑法线、锐边与三角形阴影

GBFR `.mmesh` 的位置、法线、切线、bitangent sign 和 UV0 都是逐游戏顶点存储；格式中没有 Blender 的“锐边”布尔标记。Blender 则允许一个位置顶点的不同 face corner 拥有不同法线、切线和 UV。因此正确导出必须在这些角点值不同时复制游戏顶点，并让索引、权重、颜色和 UV1 一起改指向副本。

旧导出器只按 Blender 顶点编号写一条记录，并取遇到的第一条 loop 法线/切线/UV。锐边、平面着色、UV seam 或自定义 split normal 共用一个 Blender 顶点时，其余三角面的角点数据会丢失，表现为头发等高光明显区域出现三角形阴影或法线贴图接缝。

当前插件已经改为按最终半精度的 `normal + tangent + bitangent sign + UV0 + UV1 + corner color` 签名自动复制导出顶点：

- 最小回归中，两片互成 90 度、共享两个位置点的三角面从 4 个 Blender 顶点正确导出为 6 个游戏顶点，两侧法线均保持。
- `希罗处理/输出.blend` 的 `pl1400.004/common` 需要 7,634 个角点副本，同时跳过 1 个未被任何面引用的松散点，净增加 7,633 条顶点记录；完整 LOD0 导出为 50,731 顶点、241,986 索引和 7 个材质 chunk，全部索引在范围内，chunk 无重叠且完整覆盖索引缓冲。
- 同一文件的 `fp1400.003` 四个 LOD 均通过，分别导出 6,614、3,982、2,390、844 个顶点；权重缓冲会为副本复制原顶点权重。
- UV0 固定取名为 `UV0` 的图层（缺失时取第一层），切线也明确用该层计算；切换 Blender 的活动 UV 层不会再静默改变导出。

锐边会通过 corner normal 自动生效，不要求用户额外运行“按 UV 岛拆分”。平滑面是否正确仍取决于 Blender 内可见的法线本身：若旧制作文件已经保存了错误自定义法线，需要重算法线或从修正后的导入器重新导入，导出器只能忠实保存当前 corner 数据。

## Blender 分配材质是否会“炸点序”

Blender 的 Assign Material 只修改面的 `material_index`。导出前插件会按材质排序三角面，使每个 `.minfo` chunk 对应一段连续索引，所以重新分配材质后索引缓冲顺序发生变化是必需且合法的，不是顶点坐标或蒙皮随机错位。角点副本的追加顺序也可能随面顺序变化，但每条索引仍指向对应的位置、法线、UV、颜色和权重记录。

真正的约束是 MaterialID 必须形成与 `.minfo`/MMAT 一致的编号空间。当前插件不会在删除 Blender 材质槽时同步删除所有 `vars/*.mmat` 中的同号材质，也不会自动重编号后续 MaterialID，因此“重新给面指定现有材质”可用，“删除 source 材质项”暂不作为安全操作开放。
