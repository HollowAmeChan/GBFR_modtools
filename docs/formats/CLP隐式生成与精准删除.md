# CLP 半隐式生成与精准删除

本文记录 Blender 插件“一键把所选骨链加入 CLP”、列表行精准删除、历史污染清理及保存校验所依据的格式规律和实现契约。

## 样本与结论等级

研究脚本 `scripts/research/analyze_clp.py` 已扫描完整解包数据中的 724 个 CLP，并对 236 个玩家角色 CLP 额外对照 `.skeleton` 父子关系。全量结构分布如下：

| 结构 | 文件数 | 含义 |
|---|---:|---|
| 多条独立链 | 403 | 多束头发、挂件、绳索等；链之间没有横向边 |
| 横向联网布片 | 169 | 裙摆、披风、衣物等；多条纵链之间有横向边 |
| 单链 | 100 | 辫子、绳索、短挂件等 |
| 空组 | 43 | 文件和组号存在，但节点数为 0 |
| 单点 | 9 | 只有一个求解节点 |

玩家角色中有 17 个空组。这证明保留既有文件/组号而把节点列表清空是官方存在的状态，也支持“复用现有 `0..7` 槽位”的路线。

## 已验证的拓扑不变量

- 玩家 CLP 中共有 3447 条有效 `noUp` 纵向边；与对应 `.skeleton` 比较后，3447 条全部指向该节点的真实父骨，零例外。
- `noUp/noDown` 在全部 724 个样本中都双向一致。若 A 的 `noDown=B`，B 的 `noUp` 就是 A。
- 从完整解包区重新解码的 724 个原始 CLP 共含 12122 个节点；内部 `noUp` 重复计数为 0，`noUp -> noDown` 与 `noDown -> noUp` 非互反计数也都为 0。纵向字段没有一对多树形表达。
- 对照 184 个可定位 skeleton 的模型，共找到 13 个“同组 CLP 节点在 skeleton 中共享父骨”的分叉点，涉及 26 个子节点。官方只把 10 个子节点接入纵链，另外 16 个写成 `noUp=4095`；其中 3 个分叉点连任一子支都未接入父节点。独立链会在预览中断开，属于官方存在的表达。少量布片会用 `noSide/noPoly` 连接分支链，但那是横向网格约束，不能替代纵向父子边。
- 玩家 CLP 中 1627 条有效 `noSide` 全部满足 `noPoly == noSide`；全量样本的 3500 条有效横向边也全部如此。自动生成和删除时必须把这两个字段作为同一对值原子更新。
- 玩家横向边中 1619 条只在一个方向保存。只有两个组共 8 条记录互相反向引用，属于少数特例。生成器默认写单向边即可。
- 玩家样本的横向链图可分为 88 个连通片，其中 15 个是闭环，另外 73 个是开放或不规则结构。闭环不是猜测出来的特殊格式，只是最后一串与第一串再建立一条横边。
- 236 个玩家 CLP 中，218 个文件按“第一串从根到梢、第二串从根到梢……”的顺序保存节点。运行时关系由编号引用决定，但生成器应使用这种链优先顺序得到稳定 diff。
- 同一玩家模型内，没有任何动态骨同时出现在两个 CLP 求解组。用所选骨骼编码在当前 CLP 中定位节点不会产生跨组歧义。
- `noFix` 在玩家样本中只有 4 条，既有自引用、组内引用，也有组外引用。它不是常规链生成所必需的字段；新节点默认写 `4095`，导入的非默认值作为高级覆盖保留。

`4095` 表示没有引用。所有连接写入的是导出后的骨骼名编码，不是 skeleton 数组下标。

> **2026-07-27 实机纠错：**“官方样本没有一对多纵向边”只能作为兼容基线，不能继续当作禁止实验分叉的硬限制。自定义分叉骨架把次级子支强制拆成 `noUp=4095` 后，已观察到分叉处断链拉扯。工具后续必须允许显式实验分叉，并原样保留用户选择，不能在保存时自动拆回独立 root。
>
> BXM 中每个父节点仍只有一个 `noDown`，因此实验性一对多无法保持所有边双向互反。首个待测表达是：所有子节点的 `noUp` 都指向真实父骨，父节点的 `noDown` 只指向用户指定的主支；其余子支会形成官方样本中未出现过的非互反纵边。该模式必须标记为“实验”，并在 UI/导出报告中列出非互反边，不能伪装成已验证格式。`noSide/noPoly` 仍是另一套横向约束，除非用户明确做独立对照实验，否则不应自动拿它们代替纵向分叉。

## 半隐式工作方式

生成过程可以隐式推断，但生成结果必须立即成为当前 CLP 中的显式 `CLOTH_WK` 节点，而不是等到导出时重新编译。这样用户添加后就能在现有 CLP 面板和视口中检查连接、逐节点精调参数，并且最终导出不会因为再次推断而覆盖手工修改。

常驻工具面板只保留当前 CLP 标识和添加、替换、删除、重建操作。“添加所选”或“替换当前组”点击后必须先打开创建弹窗；以下输入只在该弹窗中显示，不长期占用面板：

- 目标 CLP 槽位 `0..7`。
- 物理预设：裙摆、定型布片/袖子、长发、短发、辫子、绳索或自定义。
- 拓扑模式：独立链或横向联网。
- 横向闭合开关。
- “覆盖物理参数”开关：每次打开弹窗都默认关闭。关闭时保留目标 CLP 原有 `CLOTH_HEADER`，开启时用弹窗所选物理预设覆盖已知 Header 字段；它不控制新节点的节点级参数。
- 操作模式：追加到当前组，或先清空节点再创建。

点击添加或替换按钮时必须立即快照当前骨骼选择，弹窗确认时不得重新从不稳定的区域上下文猜测。编辑/姿态模式只要 context 返回有效当前选择，就必须将它视为权威集合，不能再并入底层残留的选择标记；仅在 context 没有任何有效骨时，才回退到 `EditBone.select/select_head/select_tail`、`PoseBone.select` 或 Blender 4.x 的 `Bone.select`。所有来源都必须过滤为当前会话骨架并按骨名去重；生成节点的五种引用还必须全部落在本次快照集合内。

操作执行后，所选预设曲线始终会烘焙成新节点的普通数值，上下游和横向边也直接写入当前内存状态。默认不改目标 CLP 已有 Header；开启“覆盖物理参数”后才同步预设 Header。用户随后可以使用现有编辑控件修改任意 Header 或节点字段。保存/构建只序列化当时显示的显式状态，不读取骨名重新推断，也不需要在骨骼上长期保存 CLP 槽位标记。

Blender 实现不能把 `FloatVectorProperty` 返回的 RNA 动态数组直接留在临时节点/碰撞数据中。追加或删除会清空并重建 `CollectionProperty`，清空后旧 RNA 数组引用失效，曾导致未参与操作的节点 `offset` 被污染。所有向量字段必须在清空前复制为普通 tuple；真实资源回归测试必须逐字段证明追加前后的旧节点完全一致。

新增骨号还可能重新激活当前组的旧悬空引用：追加前没有对应节点的 `noUp/noDown/noSide/noPoly` 不会形成有效边，但当新节点恰好取得该骨号后，旧裙摆边会突然连到新袖骨。追加合并前必须把所有目标落入本次新增骨号的旧悬空纵向/横向引用清为 `4095`，从而保持追加前的有效拓扑；允许指向组外锚骨的 `noFix` 不作此处理。

Blender Operator 应支持 Undo。工作区已有从 source 恢复单个 CLP 的能力，因此误生成、误删或参数不满意时可以 Undo、精准删除后重建，或恢复该组原文件。

## 从所选多串骨链生成

当前模型的命名已经适合直接推断，例如 `Skirt_A_01..Skirt_O_11`、`Sleeve_A_01..08_L/R`。不需要推断左右镜像。

生成步骤固定如下：

1. 收集当前所选骨骼。父骨不在选择集合中的骨骼就是各串 root。
2. 沿 Blender 父子层级生成每一串，并以 root 为深度 0。默认“官方兼容”策略仍可选择一条主支继续父链、把其余分支拆为新 root；但不得再作为唯一策略。新增“实验分叉”策略时，所有直接子节点保留 `noUp=父骨号`，父节点的单个 `noDown` 由用户指定主支；未被反向指回的子支必须在预览和导出报告中明确标红。主支未手工指定时才可用最长路径、再按骨名排序作为确定性默认。横向网格遇到分叉时也不再静默拒绝或拆链；无法自动判定行列的子支应停止自动横连，交给用户显式指定，而不是改写纵向关系。
3. 按 root 骨骼名直接升序排列各串。规范命名负责横向顺序，不使用世界坐标、左右标签或镜像推断。
4. `noUp/noDown` 只连接同一串中的真实父子骨。root 的 `noUp=4095`，梢端的 `noDown=4095`。
5. 独立链模式把所有 `noSide/noPoly` 写为 `4095`。
6. 横向联网模式在相同 depth 上连接相邻串：排序后的第 N 串节点指向第 N-1 串同深度节点，并同时写入 `noSide` 和 `noPoly`。两串长度不同时，只连接双方都存在的深度，不外推节点。
7. 开启闭合时，第一串再指向最后一串的同深度节点；关闭时保持开放边界。
8. 按 root 排序、每串从根到梢插入当前 CLP，重新计算 `CLOTH_WK_NUM`。
9. 节点曲线使用组内最大 depth 归一化，并立即烘焙成显式节点值。相同绝对 depth 的多串优先得到相同值；较短的串只是提前结束，不应各自把梢端强行拉到曲线终点。

`Skirt_0`、`Sleeve_0_L/R` 这类共同控制骨不需要自动加入。只要用户没有选择它们，每条 `*_A/B_01` 就自然成为 CLP root。

## 精准删除

精准删除直接作用于当前显式 CLP，不重新套用预设，也不改写幸存节点的物理参数。

1. 节点列表右侧的减号只删除当前高亮行，不依赖视口骨骼选择，不扩展到子节点，也不自动重建拓扑。这是长期手工精修的基础操作。
2. “删除所选”按视口当前骨骼选择删除对应节点；为兼容旧工具留下的拓扑尾端，它还会删除命中所选链末端的叶子记录。操作报告必须单独给出这些扩展删除数，不能把它伪装成列表行精准删除。
3. 扫描所有幸存节点。任何 `noUp/noDown/noSide/noPoly/noFix` 只要指向被删除 ID，就清为 `4095`，并重新计算 `CLOTH_WK_NUM`。
4. 不自动把祖父骨和孙骨桥接。官方 3447 条纵边全部是真实 skeleton 父子；跨过已删除父骨连接会破坏这个不变量。
5. 默认删除不重新排列剩余 root，也不自动跨过被删整串补横边，保证操作只影响被删节点和直接引用它的边。
6. 可另设“按当前节点重建连接”操作：点击后单独弹出连接方式和闭合开关，只按父子层级与 root 名排序重建五个引用字段，保留所有节点物理数值。用户需要消除整串删除留下的横向空隙时再主动执行。
7. 删除网格中间单个节点会造成层级断口，应立即在预览和检查结果中标出。用户可以继续选中并删除其他节点、Undo，或删掉整组后重新创建。
8. 节点数可以变为 0。此时保留 CLP Header、内部 `id_` 和空 `CLOTH_WK_LIST`，与官方空组一致。

## 历史污染检查与清理

2026-07-27 对实机异常资源审计时，`pl1400.004` 的 CLP2 共 404 条记录，其中 165 条 `bone_ref` 为空，对应骨骼对象已不存在；视口不会绘制这些节点，但它们仍会保存到 XML/BXM。清理后 CLP2 从 404 条降为 239 条，其余 CLP0/1/3/4/5/6/7 节点数保持不变，全部空引用归零。

清理不能使用别名、跨组 raw ID 或 humanoid 名称表猜测节点身份。当前导出骨架已经由用户在工具阶段完成正式命名，因此中间状态只认 `bone_ref` 直接指向的当前 Armature `Bone` 对象：

1. `bone_ref` 为空或对象不存在时，删除整条 `CLOTH_WK`；即使 raw `no` 恰好撞到 `_900` 等现存 humanoid 编号，也不得借编号“复活”。
2. 真实对象存在但其导出 ID 已更新时，以该对象当前 `gbfr_bone_id` 迁移节点 ID。
3. `noUp/noDown/noSide/noPoly` 必须通过各自 `*_ref` 指向当前组的真实存活节点，否则清为 `4095`。非互反的实验分叉只要两端对象真实存在，就不属于污染。
4. `noFix` 可以指向组外骨，但它的 `fix_ref` 仍必须是当前 Armature 中的真实对象，否则清为 `4095`。
5. “检查并清理无效节点/连接”默认扫描全部 CLP，支持 Undo，结果只修改 Blender 内存；用户确认后再保存 XML。
6. 最终模型/cloth 联合导出再次执行硬校验。每个非 `4095` 字段必须有真实骨对象，并能映射到本次实际导出的 skeleton；失败即阻止写回，禁止继续依赖 raw ID 或别名静默封包。

创建前必须报告网格分叉、重名、未能映射导出骨号和与当前组重复的节点。分叉报告必须同时显示所选策略、主支、每个子节点最终的 `noUp`，以及由单槽 `noDown` 产生的全部非互反边。删除后必须显示删除数、被清除的引用数和新产生的断链；这些冲突和结果在保存前就应可见。

## 参数呈现模型

官方参数呈现出明显的“组级固定值 + 沿深度曲线 + 少量节点覆盖”规律，而不是逐节点独立手填：

- 玩家联网布片在同一 depth 跨串完全相同的比例为：`friction 94.2%`、`gravityBlendRate_ 92.0%`、`originalRate_ 90.3%`、`weight_ 86.2%`、`offset 99.4%`、`bAllowChangeScale_ 100%`。
- `rotLimit` 大量精确使用 10、15、20、30、45、60、90、180 度对应的弧度值。
- 71 个玩家联网布片中，`rotLimit` 有 53 个从根到梢增大，`thick_` 有 52 个增大；`friction` 没有一个增大，通常保持不变或在下段降低。
- `jointScale_` 在 5020 个玩家节点中几乎总是 1；`bAllowChangeScale_` 4942 个为 0，仅 78 个为 1。它们适合作为高级开关，不适合作为默认曲线。
- 玩家节点的 `offset` 有 3536 个为 `0.1 0 0 1`，1418 个为 `0 -0.1 0 1`，只有 66 个使用其他值。它明显是方向/轴相关预设，首版应随物理预设给定并允许覆盖，不能按“强度”插值。

Blender UI 应以角度、曲线和预设呈现，但 XML 继续写原始字段。`weight_` 尚不能确认是公斤质量，`windForceArea_` 也允许负数；UI 不应把它们改名成已确认的现实物理量。

## 实现顺序

1. 解除 CLP 写回器“不能新增节点”的限制，让当前内存状态可以显式插入和删除 `CLOTH_WK`。
2. 实现从所选骨骼创建：线性链检查、root 名排序、开放/闭合横向连接和裙摆曲线烘焙。
3. 实现精准删除、悬空引用清理、Undo 和操作结果预览。
4. 实现只重建连接但保留参数的修复操作，并加入短发、长发、辫子、绳索和袖子候选预设。
5. 最后开放 Header 高级字段和 `noFix` 手工编辑。

首个游戏验证应使用 `pl1400` 组 2：把半隐式工具生成的 `Skirt_A_01..Skirt_O_11` 立即写入当前 `_0_2_clp` 状态，检查并按需精调后再保存；先测试开放和闭合两种横向连接，但暂不增加 CLH 碰撞。基础运动成立后再处理袖子和碰撞层。
