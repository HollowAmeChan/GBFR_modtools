# CLP 半隐式生成与精准删除

本文记录为 Blender 插件实现“一键把所选骨链加入 CLP”和“按所选骨骼精准删除 CLP”所需的已验证格式规律。这里描述的是实现契约，不表示这些功能已经完成。

## 样本与结论等级

研究脚本 `scripts/research/analyze_clp.py` 已扫描完整解包数据中的 724 个 CLP，并对 236 个玩家角色 CLP 额外对照 `.skeleton` 父子关系。全量结构分布如下：

| 结构 | 文件数 | 含义 |
|---|---:|---|
| 多条独立链 | 403 | 多束头发、挂件、绳索等；链之间没有横向边 |
| 横向联网布片 | 169 | 裙摆、披风、衣物等；多条纵链之间有横向边 |
| 单链 | 100 | 辫子、绳索、短挂件等 |
| 空组 | 43 | 文件和组号存在，但节点数为 0 |
| 单点 | 9 | 只有一个求解节点 |

玩家角色中有 17 个空组。这证明保留既有文件/组号而把节点列表清空是官方存在的状态，也支持“复用现有 `0..7` 槽位”的路线。

## 已验证的拓扑不变量

- 玩家 CLP 中共有 3447 条有效 `noUp` 纵向边；与对应 `.skeleton` 比较后，3447 条全部指向该节点的真实父骨，零例外。
- `noUp/noDown` 在全部 724 个样本中都双向一致。若 A 的 `noDown=B`，B 的 `noUp` 就是 A。
- 从完整解包区重新解码的 724 个原始 CLP 共含 12122 个节点；内部 `noUp` 重复计数为 0，`noUp -> noDown` 与 `noDown -> noUp` 非互反计数也都为 0。纵向字段没有一对多树形表达。
- 对照 184 个可定位 skeleton 的模型，共找到 13 个“同组 CLP 节点在 skeleton 中共享父骨”的分叉点，涉及 26 个子节点。官方只把 10 个子节点接入纵链，另外 16 个写成 `noUp=4095`；其中 3 个分叉点连任一子支都未接入父节点。独立链会在预览中断开，属于官方存在的表达。少量布片会用 `noSide/noPoly` 连接分支链，但那是横向网格约束，不能替代纵向父子边。
- 玩家 CLP 中 1627 条有效 `noSide` 全部满足 `noPoly == noSide`；全量样本的 3500 条有效横向边也全部如此。自动生成和删除时必须把这两个字段作为同一对值原子更新。
- 玩家横向边中 1619 条只在一个方向保存。只有两个组共 8 条记录互相反向引用，属于少数特例。生成器默认写单向边即可。
- 玩家样本的横向链图可分为 88 个连通片，其中 15 个是闭环，另外 73 个是开放或不规则结构。闭环不是猜测出来的特殊格式，只是最后一串与第一串再建立一条横边。
- 236 个玩家 CLP 中，218 个文件按“第一串从根到梢、第二串从根到梢……”的顺序保存节点。运行时关系由编号引用决定，但生成器应使用这种链优先顺序得到稳定 diff。
- 同一玩家模型内，没有任何动态骨同时出现在两个 CLP 求解组。用所选骨骼编码在当前 CLP 中定位节点不会产生跨组歧义。
- `noFix` 在玩家样本中只有 4 条，既有自引用、组内引用，也有组外引用。它不是常规链生成所必需的字段；新节点默认写 `4095`，导入的非默认值作为高级覆盖保留。

`4095` 表示没有引用。所有连接写入的是导出后的骨骼名编码，不是 skeleton 数组下标。

## 半隐式工作方式

生成过程可以隐式推断，但生成结果必须立即成为当前 CLP 中的显式 `CLOTH_WK` 节点，而不是等到导出时重新编译。这样用户添加后就能在现有 CLP 面板和视口中检查连接、逐节点精调参数，并且最终导出不会因为再次推断而覆盖手工修改。

常驻工具面板只保留当前 CLP 标识和添加、替换、删除、重建操作。“添加所选”或“替换当前组”点击后必须先打开创建弹窗；以下输入只在该弹窗中显示，不长期占用面板：

- 目标 CLP 槽位 `0..7`。
- 物理预设：裙摆、定型布片/袖子、长发、短发、辫子、绳索或自定义。
- 拓扑模式：独立链或横向联网。
- 横向闭合开关。
- 套用组参数开关：每次打开弹窗都默认关闭，优先保留目标 CLP 原有 `CLOTH_HEADER`；仅在用户当次明确开启时才用预设覆盖已知 Header 字段。
- 操作模式：追加到当前组，或先清空节点再创建。

操作执行后，预设曲线被烘焙成每个节点的普通数值，上下游和横向边也直接写入当前内存状态。默认不改目标 CLP 已有 Header；开启“套用组参数”后才同步预设 Header。用户随后可以使用现有编辑控件修改任意 Header 或节点字段。保存/构建只序列化当时显示的显式状态，不读取骨名重新推断，也不需要在骨骼上长期保存 CLP 槽位标记。

Blender Operator 应支持 Undo。工作区已有从 source 恢复单个 CLP 的能力，因此误生成、误删或参数不满意时可以 Undo、精准删除后重建，或恢复该组原文件。

## 从所选多串骨链生成

当前模型的命名已经适合直接推断，例如 `Skirt_A_01..Skirt_O_11`、`Sleeve_A_01..08_L/R`。不需要推断左右镜像。

生成步骤固定如下：

1. 收集当前所选骨骼。父骨不在选择集合中的骨骼就是各串 root。
2. 沿 Blender 父子层级生成每一串，并以 root 为深度 0。独立链模式允许分叉：在每个分叉点计算各子树到最深叶子的路径长度，最长分支继续父链，其余分支各自从深度 0 开始成为新的线性链；长度相同时按子骨名升序选择主链。最长分支是工具为了确定性采用的约定，不是官方通用规律；13 个官方 skeleton 分叉中只有 6 个选择了最长支，4 个选择较短支，3 个未连接任何子支。该约定仍能保留一条连续主干，且不会让一个 `noDown` 假装指向多个子骨。横向网格模式仍拒绝分叉，因为分段后已经无法无歧义地确定行列关系。
3. 按 root 骨骼名直接升序排列各串。规范命名负责横向顺序，不使用世界坐标、左右标签或镜像推断。
4. `noUp/noDown` 只连接同一串中的真实父子骨。root 的 `noUp=4095`，梢端的 `noDown=4095`。
5. 独立链模式把所有 `noSide/noPoly` 写为 `4095`。
6. 横向联网模式在相同 depth 上连接相邻串：排序后的第 N 串节点指向第 N-1 串同深度节点，并同时写入 `noSide` 和 `noPoly`。两串长度不同时，只连接双方都存在的深度，不外推节点。
7. 开启闭合时，第一串再指向最后一串的同深度节点；关闭时保持开放边界。
8. 按 root 排序、每串从根到梢插入当前 CLP，重新计算 `CLOTH_WK_NUM`。
9. 节点曲线使用组内最大 depth 归一化，并立即烘焙成显式节点值。相同绝对 depth 的多串优先得到相同值；较短的串只是提前结束，不应各自把梢端强行拉到曲线终点。

`Skirt_0`、`Sleeve_0_L/R` 这类共同控制骨不需要自动加入。只要用户没有选择它们，每条 `*_A/B_01` 就自然成为 CLP root。

## 精准删除

精准删除直接作用于当前显式 CLP，不重新套用预设，也不改写幸存节点的物理参数。

1. 把当前所选骨骼映射为导出骨骼编码，只删除当前组中 `no` 命中的节点。删除范围严格等于用户选择，不隐式扩展到后代。
2. 扫描所有幸存节点。任何 `noUp/noDown/noSide/noPoly/noFix` 只要指向被删除 ID，就清为 `4095`，并重新计算 `CLOTH_WK_NUM`。
3. 不自动把祖父骨和孙骨桥接。官方 3447 条纵边全部是真实 skeleton 父子；跨过已删除父骨连接会破坏这个不变量。
4. 默认删除不重新排列剩余 root，也不自动跨过被删整串补横边，保证操作只影响被删节点和直接引用它的边。
5. 可另设“按当前节点重建连接”操作：点击后单独弹出连接方式和闭合开关，只按父子层级与 root 名排序重建五个引用字段，保留所有节点物理数值。用户需要消除整串删除留下的横向空隙时再主动执行。
6. 删除网格中间单个节点会造成层级断口，应立即在预览和检查结果中标出。用户可以继续选中并删除其他节点、Undo，或删掉整组后重新创建。
7. 节点数可以变为 0。此时保留 CLP Header、内部 `id_` 和空 `CLOTH_WK_LIST`，与官方空组一致。

创建前必须报告网格分叉、重名、未能映射导出骨号和与当前组重复的节点。独立链分叉应显示为实际生成的链段结果。删除后必须显示删除数、被清除的引用数和新产生的断链；这些冲突和结果在保存前就应可见。

## 参数呈现模型

官方参数呈现出明显的“组级固定值 + 沿深度曲线 + 少量节点覆盖”规律，而不是逐节点独立手填：

- 玩家联网布片在同一 depth 跨串完全相同的比例为：`friction 94.2%`、`gravityBlendRate_ 92.0%`、`originalRate_ 90.3%`、`weight_ 86.2%`、`offset 99.4%`、`bAllowChangeScale_ 100%`。
- `rotLimit` 大量精确使用 10、15、20、30、45、60、90、180 度对应的弧度值。
- 71 个玩家联网布片中，`rotLimit` 有 53 个从根到梢增大，`thick_` 有 52 个增大；`friction` 没有一个增大，通常保持不变或在下段降低。
- `jointScale_` 在 5020 个玩家节点中几乎总是 1；`bAllowChangeScale_` 4942 个为 0，仅 78 个为 1。它们适合作为高级开关，不适合作为默认曲线。
- 玩家节点的 `offset` 有 3536 个为 `0.1 0 0 1`，1418 个为 `0 -0.1 0 1`，只有 66 个使用其他值。它明显是方向/轴相关预设，首版应随物理预设给定并允许覆盖，不能按“强度”插值。

Blender UI 应以角度、曲线和预设呈现，但 XML 继续写原始字段。`weight_` 尚不能确认是公斤质量，`windForceArea_` 也允许负数；UI 不应把它们改名成已确认的现实物理量。

首轮只需要预设曲线和显式单节点编辑，不需要复制原工具所有未知控制项。创建器必须保留当前 Header 的未识别字段，生成后立即在预览中显示实际节点和连接；导出器只负责序列化这份已经确认的状态。

## 实现顺序

1. 解除 CLP 写回器“不能新增节点”的限制，让当前内存状态可以显式插入和删除 `CLOTH_WK`。
2. 实现从所选骨骼创建：线性链检查、root 名排序、开放/闭合横向连接和裙摆曲线烘焙。
3. 实现精准删除、悬空引用清理、Undo 和操作结果预览。
4. 实现只重建连接但保留参数的修复操作，并加入短发、长发、辫子、绳索和袖子候选预设。
5. 最后开放 Header 高级字段和 `noFix` 手工编辑。

首个游戏验证应使用 `pl1400` 组 2：把半隐式工具生成的 `Skirt_A_01..Skirt_O_11` 立即写入当前 `_0_2_clp` 状态，检查并按需精调后再保存；先测试开放和闭合两种横向连接，但暂不增加 CLH 碰撞。基础运动成立后再处理袖子和碰撞层。
