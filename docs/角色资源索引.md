# 角色资源索引：Model ID 与 `.minfo` 路径

本文把已探明的可操作角色 Model ID 与游戏数据中的相对路径对应起来，便于从角色名称反查 `.minfo`。路径均相对于游戏 `data/` 根目录；`filelist.txt` 是本机当前解包索引，位置记录在 [本机资源路径](本机资源路径.md)。

## 范围与判定规则

- 主表收录公开 Model IDs 中的玩家角色（`pl`），以及 `filelist.txt` 中存在的本地变体。
- `model/pl/.../*.minfo` 是身体模型入口；标准头部/脸部入口位于 `model/fp/.../*.minfo`，武器入口位于 `model/wp/.../*.minfo`。
- NPC 头部/脸部使用 `fn` 前缀（例如罗兰的 `fn0300`）；`fn` 不应与玩家的 `fp` 目录混用。
- `fp` 不会为每一个 `pl` 变体重复建立目录。表中只列实际存在的 `fp` `.minfo`；缺失项表示复用标准头部或没有独立头部入口。
- 武器按角色编号前两位组成家族（例如 `pl1400` 对应 `wp14xx`）。`xx` 不是字面目录名，实际武器 ID 必须在 `filelist.txt` 中查到。
- 身体/头部的正式流式网格通常位于 `model_streaming/lod0..3/<id>.mmesh`；`.minfo` 同目录下不一定有 `.mmesh`，不要把缺少同目录网格当成资源缺失。
- `pl2400`/`pl2500` 是可操作角色入口，但还各自有独立的敌人入口；这两组不能按数字合并。

### 表中 `fp` 写法

单元格只写 `fp0000`、`fp0100` 或 `fp1100` 时，表示该行复用同 ID 的完整路径。例如 `pl1101` 的头部入口仍是 `model/fp/fp1100/fp1100.minfo`。当前实际存在的标准 `fp` 入口为：

```text
fp0000 fp0100 fp0200 fp0300 fp0400 fp0500 fp0600 fp0700 fp0800 fp0900
fp1000 fp1100 fp1200 fp1300 fp1400 fp1500 fp1600 fp1700 fp1800 fp1900
fp2000 fp2100 fp2200 fp2300 fp2400 fp2500 fp2600 fp2700 fp2800 fp2900
```

没有发现 `fp0001`、`fp0101`、`fp1101`、`fp1102` 或 `fp2801` 的 `.minfo`。其中 `pl0001`、`pl0101`、`pl1101`、`pl1102` 的标准头部复用关系较明确；`pl2801` 先以 `fp2800` 作为候选，仍应通过模型预览或场景引用确认。这是文件索引事实，不代表对应 `pl` 身体不能使用。

## 从 `filelist.txt` 复核

以下命令只读索引，不会访问或修改游戏文件：

```powershell
$fileList = 'D:\Steam\steamapps\common\Granblue Fantasy Relink\GBFRDataTools-win-x64\win-x64\filelist.txt'

# 所有已知玩家主体 minfo
rg -i '^model/pl/pl(0000|0001|0100|0101|0200|0300|0400|0500|0600|0700|0800|0900|1000|1100|1101|1102|1200|1300|1400|1500|1600|1700|1800|1900|2000|2100|2200|2300|2400|2500|2600|2700|2800|2801|2900)/.*\.minfo$' $fileList

# Gallanza / Maglielle 双实体
rg -i '^model/(pl/pl2400|fp/fp2400|em/em2000|pl/pl2500|fp/fp2500|em/em2100)/.*\.minfo$' $fileList
```

公开名称与编号的参考是 [Relink Modding Model IDs](https://nenkai.github.io/relink-modding/resources/model_ids/)，角色配色入口可对照 [Character Colors / Packs](https://nenkai.github.io/relink-modding/resources/other/color_packs/)，表格类别说明见 [Table List](https://nenkai.github.io/relink-modding/tables/table_list/)，`.minfo` 的格式说明见 [Relink Modding `.minfo`](https://nenkai.github.io/relink-modding/resources/formats/minfo/)。网页名称表是人名基线，实际“文件是否存在”以本机 `filelist.txt` 为准。

## 罗兰作为可操作角色的独立资源调查

罗兰的可操作角色 Mod 不应建立在“共享某个 `pl` 角色资源”的假设上。本机索引已经找到一套独立的 NPC 资源链。当前提取器只按与玩家工作区相同的资源层收集：模型、LOD、动作、cloth、材质、贴图和 UI；系统参数、FSM、语音和事件动作暂不纳入基础提取。

## 与角色工作区的关系

选择某个 `plXXXX` `.minfo` 生成工作区时，编辑器会将主体模型放入 `model/pl/plXXXX/`，并按实际存在的相同数字 ID 收集 `fp`、`wp`、流式网格、材质和 UI 资源。工作区内的路径仍保持 `data/` 后的相对路径；只编辑 `unpack/data/`，`source/data/` 作为基线，`build/data/` 作为最终输出。详细规则见 [工作区与格式说明](工作区与格式说明.md)。

玩家角色表与 NPC 表使用不同的实体前缀：`pl/fp/wp` 是玩家身体、头部和武器，`np/fn` 是 NPC 身体和头部。后续扩展 NPC 场景或行为资源时，应以本节的实际 `.minfo` 入口为起点，不要把 `np` 路径按数字直接拼到玩家角色的 `pl` 行。
